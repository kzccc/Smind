# HTML 函数调用图经验

## 2026-08-13 PromptOps 接口调用图

- 单文件 HTML 必须写完整文档外壳：`<!doctype html>`、`<html lang="zh-CN">`、`<meta charset="utf-8">`。只写片段式 `<div>` 容易在本地 `file://` 打开时出现中文编码异常。
- SVG 节点内多行文本不要用过近的固定 y 坐标。尤其是 `label`、`file`、`sub` 三行，节点高度不足时会重叠；应统一设置最小节点高度，并对长文本做截断或换行。
- 调用图的边不要固定从“源节点右侧中心”连到“目标节点左侧中心”。上下游节点存在上下错位、反向或垂直布局时，箭头会穿过节点或对不齐；应根据两个节点中心点相对方向计算边界锚点。
- 静态布局很难避免跨节点连线。对调用关系图，节点应支持拖拽，拖动后实时重算连线，让使用者可以手动整理复杂链路。
- 节点选中态不要只改节点边框颜色，容易和 hover 混在一起。更清晰的做法是在节点外额外画一层红色包围框，表示右侧详情当前对应的节点。
- 右侧详情里不要重复展示“调用下游/相关结构体”列表，信息会噪声化。结构体跳转应直接做在源码中的结构体名上，点击源码里的类型名打开左侧结构体详情。
- 详情面板的前进/后退应按“节点点击历史”维护，类似 VSCode 导航，而不是浏览器历史。点击节点 push history，后退/前进只切换当前函数详情和节点选中态。
- 左右侧栏拖拽不要设置固定上限。只要中间画布保留最小可用宽度，拖动一侧时可以压缩另一侧，避免用户想看源码时被最大宽度限制卡住。
- `node --check` 只能检查脚本语法，不能证明 DOM 交互可用。完成后至少用浏览器/Playwright 打开本地 HTML，检查节点数量、边数量、控制台错误、字体和基础交互。
- 如果视觉要求是“线条都是曲线”，SVG path 里不要混入 `L` 直线段。即使入口和出口是贝塞尔，只要中间避让通道用了 `L`，用户看到的仍然是僵直折线；应把通道也拆成连续 `C` 贝塞尔曲线。
- 如果用户要求“端点可移动 + 中间箭头”，不要再用 `marker-end`。更合适的结构是每条边拆成 path、from circle、to circle、mid-arrow 四个 SVG 元素：圆点用 `{side,t}` 绑定到节点矩形边缘，拖动时把鼠标投影到最近边；中间箭头用 `getTotalLength/getPointAtLength` 取曲线真实中点和切线方向。
- 多条边连接同一个节点同一条边时，端点不要都默认放在 `t=0.5`，否则圆点重叠、点击不稳定。初始化时应按节点边和目标方向分组，把 `t` 均匀分散；点击某条边时要把 path、mid-arrow 和两个端点移动到对应图层最后，并用透明粗 hit-path 增大命中区域。
- 曲线控制点距离要克制。端点距离较近或同侧连接时，过大的贝塞尔切线距离会绕成圆环；建议按端点距离自适应，并限制上限，例如 `distance = clamp(28, 110, hypot * 0.18)`。
- 避让通道不能只按“画布上半区/下半区”选择，否则端点在节点上边时可能被通道拉到节点下方，视觉上像线从方框底部钻出来。应按端口方向选择通道：top 端口走节点上方，bottom 端口走节点下方，首尾控制点沿端口法线离开节点。
- 不要为了避让强行插入远处中转点，例如 `(midX,laneY)`，这会把贝塞尔拆成类似发卡弯/V 形大转弯。更稳定的做法是单段受限贝塞尔：控制点主要沿端点直线方向推进，只叠加很小的法线 bend，保证线条始终短、顺、可预测。
- 源代码面板里的“下游调用”不要再额外做列表；更像 VSCode 的做法是直接把源码中的函数字面量渲染成可点击链接。点击函数名应切换右侧函数详情、同步节点红框，并 push 到节点点击历史；后退/前进按钮只在这套节点历史中移动，不做调用链遍历。
- 结构体跳转和函数跳转要在源码中区分：函数链接用于右侧节点导航，结构体链接用于左侧结构体详情。不要让两类链接互相覆盖，替换源码时按最长字面量优先，并使用同一轮正则替换，避免嵌套 span。
- 节点卡片中的一句解释如果要支持人工修订，应在右侧详情增加“函数注释”编辑区，并把输入实时同步回节点卡片的说明文本和 title。这个状态可以先保存在单文件 HTML 的内存里，后续如果需要持久化再追加 localStorage/export。
- 项目型 HTML 产物不要放进业务仓库的 docs 临时目录。此类调用图统一放到 `api-html-skill/项目/<repo>/`，经验沉淀继续追加到 `api-html-skill/经验积累/`，避免污染正式业务仓库。
